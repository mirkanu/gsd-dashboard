# Plan 67-01: Install Cockpit + Expose via Cloudflare Tunnel

## Goal

Install Cockpit on the Hetzner VPS and expose it at `cockpit.gsdlabs.dev` via the existing
named Cloudflare Tunnel so server metrics (CPU, RAM, disk, processes, systemd, journal) are
accessible in the browser without SSH.

## Context

- VPS: Ubuntu 24.04 LTS, SSH as `claude@37.27.212.18` via `~/.ssh/hetzner_claude`
- Cockpit default port: 9090, uses self-signed TLS
- Tunnel config: `/home/claude/.cloudflare-tunnel/config.yml` on VPS
- Tunnel is managed by PM2 (`gsd-tunnel`) — restart needed after config change
- Current tunnel ingress: dashboard, debates, ynab, kidai, api, zoho-sync, librechat

## Tasks

### Task 1 — Install Cockpit

<read_first>
- Run `dpkg -l cockpit` on VPS first to confirm it's not installed
</read_first>

<action>
SSH to VPS and install cockpit:

```bash
sudo apt-get update && sudo apt-get install -y cockpit
```

Enable and start the socket unit (Cockpit uses socket activation):
```bash
sudo systemctl enable --now cockpit.socket
```

Verify it's listening:
```bash
sudo systemctl is-active cockpit.socket
curl -sk https://localhost:9090/ | grep -i cockpit || echo "responding"
```
</action>

<acceptance_criteria>
- `systemctl is-active cockpit.socket` outputs `active`
- `curl -sk https://localhost:9090/` returns HTML (not connection refused)
</acceptance_criteria>

### Task 2 — Add Cockpit ingress rule to Cloudflare Tunnel config

<read_first>
- `/home/claude/.cloudflare-tunnel/config.yml` on VPS (current ingress rules)
</read_first>

<action>
Add a new ingress rule for `cockpit.gsdlabs.dev` to the tunnel config.

Cockpit uses self-signed TLS, so the tunnel must use `https://` with `noTLSVerify: true`.

Insert before the catch-all `http_status:404` line:

```yaml
  - hostname: cockpit.gsdlabs.dev
    service: https://localhost:9090
    originRequest:
      noTLSVerify: true
```

Full updated ingress section:
```yaml
ingress:
  - hostname: dashboard.gsdlabs.dev
    service: http://localhost:4820
  - hostname: debates.gsdlabs.dev
    service: http://localhost:3000
  - hostname: ynab.gsdlabs.dev
    service: http://localhost:3001
  - hostname: kidai.gsdlabs.dev
    service: http://localhost:3002
  - hostname: api.gsdlabs.dev
    service: http://localhost:5000
  - hostname: zoho-sync.gsdlabs.dev
    service: http://localhost:3003
  - hostname: librechat.gsdlabs.dev
    service: http://localhost:3004
  - hostname: cockpit.gsdlabs.dev
    service: https://localhost:9090
    originRequest:
      noTLSVerify: true
  - service: http_status:404
```
</action>

<acceptance_criteria>
- `grep cockpit /home/claude/.cloudflare-tunnel/config.yml` returns the hostname line
- `grep noTLSVerify /home/claude/.cloudflare-tunnel/config.yml` returns `noTLSVerify: true`
</acceptance_criteria>

### Task 3 — Add Cloudflare DNS record for cockpit.gsdlabs.dev

<read_first>
- `cloudflared tunnel list` on VPS to confirm tunnel UUID is `093489ad-5644-4b42-a6c6-32c45c244fed`
</read_first>

<action>
Add a CNAME record in Cloudflare DNS for `cockpit.gsdlabs.dev` pointing to the tunnel:

```bash
cloudflared tunnel route dns gsd-dashboard cockpit.gsdlabs.dev
```

This creates a CNAME `cockpit.gsdlabs.dev` → `{tunnel-uuid}.cfargotunnel.com`.
Run as the `claude` user on the VPS.
</action>

<acceptance_criteria>
- `cloudflared tunnel route dns gsd-dashboard cockpit.gsdlabs.dev` exits 0, or outputs "record already exists"
- OR: DNS record visible via `cloudflared tunnel route dns list` or Cloudflare dashboard
</acceptance_criteria>

## Threat Model

- **T-67-01:** Cockpit exposes full server admin — authentication is PAM (OS users). The `claude`
  user password must be non-trivial. If Cockpit is reachable publicly, brute-force is possible.
  Mitigation: Cloudflare Access can be added later to gate the subdomain behind email auth.
- **T-67-02:** noTLSVerify=true bypasses cert validation for the localhost leg only (tunnel → Cockpit).
  The public-facing leg (user → Cloudflare) is still TLS-encrypted. Acceptable for localhost.
- **T-67-03:** `cloudflared tunnel route dns` requires Cloudflare API token in the environment.
  If it fails, add the CNAME manually in Cloudflare dashboard: cockpit.gsdlabs.dev CNAME → 093489ad-5644-4b42-a6c6-32c45c244fed.cfargotunnel.com (proxied).

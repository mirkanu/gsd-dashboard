## Component Specification: `/gsd-next` Chip Button

### Location
Render `CommandChips` directly above the `SendBox` in the `TerminalOverlay` component, inside the `{isMobile && ...}` gate (send box is mobile-only, but see desktop note below).

**Desktop note:** On desktop, the send box (`SendBox`) is currently not shown — but the `GSD_CHIPS` constant and `CommandChips` component are wired to populate it when shown. The `CommandChips` row should render in the mobile send-box area only, consistent with the existing `isMobile` gate around `SendBox`.

**Exact placement:** Between `SendBox` and `SpecialKeyBar` in the JSX tree, inside the `flex-shrink-0` wrapper div.

### Button appearance
Use the existing `CommandChips` component unchanged. Match this exact className pattern from `CommandChips.tsx`:

```
px-3 py-1 rounded-full border border-accent/20 bg-accent/5 text-xs text-accent hover:bg-accent/10 active:scale-[0.98] transition-all
```

### New entry in `GSD_CHIPS`
Add `/gsd-next` as the **first** item in the `GSD_CHIPS` array (highest discoverability position):

```typescript
const GSD_CHIPS = [
  "/gsd-next",
  "/gsd-resume-work",
  "/gsd-progress",
  "/gsd-pause-work",
  "/gsd-plan-phase",
] as const;
```

### Interaction
- Clicking a chip calls `onSelect(cmd)` which calls `api.gsd.send(projectName, cmd)` — same as the send box submit handler.
- On mobile, after sending, the chip row stays visible (no state change needed).
- No loading/sent/error state on chips — the send box below handles feedback for freeform input; chips are fire-and-forget.

## Accessibility

- Chip buttons are `<button>` elements (already the case in `CommandChips.tsx`).
- Add `aria-label="GSD command shortcuts"` to the `CommandChips` wrapper div.
- Each chip's accessible label is its visible text (e.g. `/gsd-next`) — no additional `aria-label` needed per chip.
- Touch target: `px-3 py-1` renders approximately 28–32px tall on mobile. Within acceptable range for a shortcut row (not a primary action). No 44px exception required.

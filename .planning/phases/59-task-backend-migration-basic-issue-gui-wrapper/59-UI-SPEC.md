## Component Behaviour & States

### 1. StageTransitionModal — Migration Step

**When:** User clicks stage button targeting Launched in StageTransitionModal (from Phase 58)

**Before migration step shown:**
- Check `project.github_repo` exists (set during project creation in Phase 51)
- If missing, skip migration step and jump to confirmation
- If present, insert migration step BEFORE the final confirmation

**Migration step layout:**
```
┌─────────────────────────────────┐
│ Advance to Launched?            │
├─────────────────────────────────┤
│                                 │
│ Back up your tasks to GitHub?   │ ← Heading
│ Your Dashboard tasks will be    │ ← Description
│ exported as GitHub Issues...    │
│                                 │
│ ☐ Migrate tasks to GitHub      │ ← Toggle (unchecked by default)
│   If unchecked, tasks stay...  │ ← Explanation
│                                 │
│ [Cancel]  [Confirm & Migrate]   │ ← Buttons (label changes based on toggle state)
│           or [Confirm]          │
└─────────────────────────────────┘
```

**State transitions:**
- Toggle OFF (default): button says "Confirm"
- Toggle ON: button says "Confirm & Migrate", button color remains accent
- During migration: button disabled, label becomes "Confirming & Migrating…"
- On migration error: red error box shown above buttons, retry inline or cancel

**Accessibility:**
- Toggle has associated label clickable as text
- Error messages announced via role="alert"
- Escape key closes modal (existing Phase 58 behavior)

### 2. TasksTab — GitHub Backend Render

**When:** `project.task_backend === 'github'` (set after successful migration)

**Layout (replaces entire task list):**
```
┌─────────────────────────────────┐
│ GITHUB BACKEND STATE            │
├─────────────────────────────────┤
│                                 │
│ {N} issues migrated to GitHub   │ ← Info text (14px, Gray-400)
│                                 │
│ [Open GitHub Issues →]          │ ← Primary button (accent color)
│                                 │
│ [Restore Dashboard Tasks]       │ ← Conditional: if within 7 days since migration
│ (visible only within 7 days)    │
│                                 │
└─────────────────────────────────┘
```

**Button sizes & spacing:**
- All buttons: `inline-flex items-center gap-2 px-4 py-2 bg-accent hover:bg-accent-hover text-white text-sm font-medium rounded-lg`
- Vertical gap between elements: 16px (md)
- Buttons stacked vertically

**Issue count retrieval:**
- Try to fetch live count from GitHub API if PAT available
- On fetch error, show "Tasks migrated to GitHub" (no count)
- Live count is optional enhancement (not blocking)

**Rollback button visibility:**
- Parse `taskMigratedAt` from project config
- Show "Restore Dashboard Tasks" button ONLY if `Date.now() - taskMigratedAt < 7 days` (604800000 ms)
- Button color: Tailwind red-600 (destructive, confirms user understands this is a rollback)
- Clicking rollback: show inline confirmation "This will restore your Dashboard tasks. Continue?" before executing

### 3. TasksTab — Dashboard Backend + GitHub Eligible

**When:** `project.task_backend === 'dashboard'` AND project has `github_repo` field set AND transition was skipped or user hasn't migrated yet

**Layout (prepend to existing task list):**
```
┌─────────────────────────────────┐
│ MIGRATION OPTION BANNER         │
├─────────────────────────────────┤
│                                 │
│ Migrate your tasks to GitHub    │ ← Info text (14px, Gray-400)
│ [Migrate to GitHub]             │ ← Secondary button
│                                 │
└─────────────────────────────────┘
[Existing task list below...]
```

**Button:**
- `inline-flex items-center gap-2 px-4 py-2 bg-surface-4 hover:bg-border text-gray-300 hover:text-gray-200 text-sm font-medium rounded-lg` (secondary/ghost style)
- Tooltip (title attr): "Export your Dashboard tasks as GitHub Issues"

**Interaction:**
- Clicking opens a simple confirmation modal: "Export all N open tasks to GitHub?" with details
- Modal has "Cancel" and "Migrate" buttons
- On success, TasksTab re-renders to GitHub backend state (requires data refetch)

### 4. Type Contract Updates

**GsdProject interface additions:**
```typescript
task_backend: 'dashboard' | 'github';      // Defaults to 'dashboard'
github_repo?: string;                       // e.g. "owner/repo", set during creation or migration
taskMigratedAt?: string;                    // ISO timestamp of successful migration
```

**Data flow:**
- `task_backend` written to `gsd-projects.json`
- `taskMigratedAt` written to `gsd-projects.json` on successful migration
- TasksTab reads these fields to decide which render branch to show

## Interaction Patterns (Reference)

### Migration Flow Diagram
```
User clicks "Advance to Launched" 
  ↓
StageTransitionModal opens
  ↓
validateStageTransition API called
  ↓
IF project has GitHub repo:
  Show migration step toggle
  ↓
  User decides: toggle ON or OFF
  ↓
  IF toggle ON:
    Export tasks via POST /api/projects/:name/migrate-tasks
    Save snapshot: .dashboard-task-snapshot-{timestamp}.json
    Set task_backend = 'github' in gsd-projects.json
    Set taskMigratedAt = now() in gsd-projects.json
    ↓
    TasksTab re-renders showing GitHub backend state
    ↓
    For 7 days: show rollback button
    ↓
  IF toggle OFF:
    Skip migration, proceed to stage PATCH
    ↓
    TasksTab shows migration banner (optional button to migrate later)
ELSE (no GitHub repo):
  Skip migration step entirely
  ↓
  Proceed to stage PATCH
```

### Rollback Flow Diagram
```
User clicks "Restore Dashboard Tasks" button (within 7 days)
  ↓
Inline confirmation shown
  ↓
User confirms
  ↓
Load snapshot from .dashboard-task-snapshot-{timestamp}.json
  ↓
Restore tasks to project_tasks table
  ↓
Set task_backend = 'dashboard' in gsd-projects.json
  ↓
Clear taskMigratedAt
  ↓
TasksTab re-renders showing Dashboard backend + migration banner
```

## Error States

### Migration Failure (partial)

**Display:** Modal stays open after "Confirm & Migrate" click

```
┌─────────────────────────────────┐
│ Advance to Launched?            │
├─────────────────────────────────┤
│                                 │
│ ✗ Failed to export 3 of 12 tasks│ ← Red error box
│ Check your GitHub PAT and repo  │
│ access, then click Retry.       │
│                                 │
│ [Cancel]  [Retry]               │ ← "Migrate" button becomes "Retry"
│                                 │
└─────────────────────────────────┘
```

- Retry mechanism: POST `/api/projects/{name}/migrate-tasks?retry=true` (skip already-exported)
- On final success: close modal, refresh TasksTab to GitHub backend state
- On third retry failure: offer "Skip migration" option instead of forcing retry

### Rollback Failure

**Display:** In-place error message above rollback button

```
✗ Failed to restore tasks. 
Check the snapshot file exists at {path}. 
[Retry]
```

## Notes for Executor

### Integration Points
1. **StageTransitionModal.tsx** — Add migration step before final confirmation; check `project.github_repo` exists
2. **TasksTab.tsx** — Add conditional render based on `project.task_backend` field
3. **types.ts** — Extend `GsdProject` interface with `task_backend`, `github_repo`, `taskMigratedAt`
4. **Backend API** — POST `/api/projects/{name}/migrate-tasks` (exports tasks to GitHub, returns task count)
5. **Backend API** — POST `/api/projects/{name}/rollback-tasks` (restores from snapshot, flips backend back to 'dashboard')

### Key Decisions Locked In
- **D-01:** Migration prompted (not forced) during Beta→Launched transition
- **D-02:** Skip option always available; migrate-later button appears in TasksTab
- **D-03:** Only projects with GitHub remote eligible (no error for projects without remote)
- **D-04:** GitHub repo URL read from git remote, stored as `github_repo` field
- **D-05:** Migration preserves task creation date and Dashboard task ID in issue body
- **D-07:** `task_backend` defaults to 'dashboard', flips to 'github' only after successful full export
- **D-08:** TasksTab content replaced entirely; no dual listing after migration
- **D-10/D-11:** 7-day rollback window using JSON snapshot in project root

### Implementation Caution
- **Snapshot filename format:** User's discretion (e.g., `.dashboard-task-snapshot-{iso-timestamp}.json`)
- **Label color for source:dashboard-migration:** Default GitHub label gray-400 acceptable (no custom color required)
- **Issue count display:** Optional enhancement (gracefully omitted if API unavailable)

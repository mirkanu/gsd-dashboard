## Interaction Patterns

### Stage Transition Modal Flow (MAT-03)

1. User clicks "Advance to [Stage]" button on ProjectCard
2. Modal opens, fetches gate validation via `/api/projects/:name/stage/validate` POST
3. Gates render as checklist (✓ pass / ✗ fail / ⚠ warning)
4. If hard gates fail → button disabled "Cannot advance"
5. If hard gates pass → button enabled "Confirm & Auto-Create" (if provisioning) or "Confirm"
6. User clicks Confirm → PATCH `/api/projects/:name/stage` with target stage
7. Modal shows loading spinner while transition completes
8. On success → modal closes, ProjectCard re-renders with new stage, Portfolio Feed logs event
9. On error → modal shows error message, stays open for retry

### Backfill Flow (MAT-06)

1. Unassigned project renders inline "Assign stage" chip
2. User clicks chip → backfill modal opens (6 stage options, radio select)
3. User selects stage → clicks "Confirm"
4. Modal calls `/api/projects/:name/stage` PATCH with selected stage
5. On success → chip disappears, stage badge appears on card
6. On error → modal shows error, stays open

### Kill/Archive Flow (MAT-08)

1. Draft-stage ProjectCard shows "Archive" button in action menu
2. User clicks "Archive" → modal asks "Archive [project]?"
3. Modal shows two options: "Archive" (non-destructive) or "Delete permanently" (destructive)
4. If "Archive" → modal closes, PATCH `/api/projects/:name/archive`, card hidden, Portfolio Feed event logged
5. If "Delete permanently" → modal transitions to delete confirmation (requires typing "DELETE")
6. User types "DELETE" in input → button enables
7. User clicks "Delete" → DELETE `/api/projects/:name`, card removed, Portfolio Feed event logged

### Stage Grouping View (MAT-02)

1. User clicks "Group by Stage" toggle in ChatListFilters
2. Dashboard layout switches from State tabs (Waiting/Working/Paused) to stage groups
3. Projects re-render grouped under headers: "📝 Draft (2)", "🚀 Launched (1)", etc.
4. Same ProjectCard UI used in both views
5. User can toggle back to "Group by State" anytime (stateless toggle)

### Nudge Display (MAT-07)

1. Server-side cron or event check calculates stage nudge eligibility
2. If eligible → Portfolio Feed pushes nudge event
3. FeedPage renders nudge as special event type with "Start transition" link
4. Same event also renders as card badge "⬆ Ready to advance" on ProjectCard
5. User can dismiss badge or click to start transition modal

## States & Responsive Behavior

### Modal & Dialog States

- **Loading:** Spinner overlay + disabled button
- **Gate validation error:** Red error message, "Try again" button
- **Soft gate warning:** Yellow ⚠ icon, non-blocking proceed
- **Hard gate failure:** Red ✗ icon, button disabled
- **Concurrent transition:** Modal locked, shows "Transition in progress..."

### Button States

- **Enabled:** Full color, hover darker shade
- **Disabled:** Opacity 50%, cursor not-allowed
- **Loading:** Spinner inside, text changes to "Advancing..." / "Archiving..."

### Responsive Behavior (Mobile)

- Modal max-width on small screens: 90vw (mobile-safe)
- Kill/Archive modal: inline "DELETE" input (full-width)
- Stage grouping: preserves section headers on mobile (no horizontal scroll)
- ProjectCard badges: badge size reduced to 11px on screens < 640px if needed (stretch goal)

## API Contract (Frontend Assumptions)

### Endpoints Called by UI

| Method | Path | Request | Response | Error |
|--------|------|---------|----------|-------|
| POST | /api/projects/:name/stage/validate | { to: "stage" } | { valid: bool, hardGates: [], softGates: [] } | 400 + error description |
| PATCH | /api/projects/:name/stage | { to: "stage" } | { success: bool, stage: "stage", project: {} } | 500 + detail |
| POST | /api/projects/:name/archive | { } | { success: bool } | 500 + detail |
| DELETE | /api/projects/:name | { } | { success: bool } | 500 + detail |

**Source:** RESEARCH.md §Architecture Patterns §Pattern 3 documents the backend contract; frontend assumes these endpoints exist.

## Accessibility & Keyboard Navigation

- Modal trap focus (Tab loops inside modal, Escape closes)
- Stage badge: aria-label describing stage (e.g., "Project is in Beta")
- Buttons: clear focus ring (outline), keyboard-accessible via Tab
- Gate messages: aria-live region for async validation results
- Section headers: semantic `<h3>` for stage grouping sections
- "DELETE" confirmation input: autofocus on mount (mobile UX)

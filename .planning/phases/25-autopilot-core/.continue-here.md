## Critical: Autopilot can't send commands into active Claude Code sessions

The `processSpawner` uses `tmux send-keys -t {session} {command} Enter` to type GSD slash commands into tmux.
This **doesn't work** when Claude Code is already active in that session — the text appears but Claude Code
is mid-operation and can't process a new slash command.

**Fix options (choose one):**
1. **Wait for idle prompt** — before spawning, poll tmux pane for the `❯` prompt (Claude Code idle indicator). Only send-keys when idle.
2. **Use a separate tmux window** — spawn a new tmux window in the same session for each autopilot command, so it doesn't interfere with the active session.
3. **Queue approach** — AutopilotManager waits for the current command to finish (detected via STATE.md progress change) before sending the next one. This is partially implemented already (the poll loop), but the FIRST command send also needs to wait for idle.

**Recommended: Option 1** — simplest, matches existing `detectSessionState()` in `server/gsd/tmux.js` which already reads tmux pane output. Add a `waitForIdle(sessionName, timeoutMs)` function that polls until `❯` prompt is visible, then send-keys.

## Also fix: Silent error swallowing in UI

The `catch { /* silent */ }` blocks in AutopilotControls handlers mean users see nothing when API calls fail.
Replace with toast notifications (sonner) showing the error message.

## Also fix: Error feedback from autopilot

When autopilot starts but fails silently (e.g., the spawned command doesn't execute), there's no feedback on the card.
The card should show error state, not just go back to idle.
</remaining_work>

```sql
CREATE TABLE IF NOT EXISTS project_settings (
  project_key TEXT PRIMARY KEY,
  verbosity TEXT NOT NULL DEFAULT 'normal' CHECK(verbosity IN ('verbose','normal','quiet')),
  telegram_alerts TEXT NOT NULL DEFAULT '{}',
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))
```

<task type="auto">
  <name>Task 2: Create config routes for CLAUDE.md read/write and project settings CRUD</name>
  <files>server/routes/config.js, server/routes/gsd.js</files>
  <action>
Create `server/routes/config.js` with the following endpoints:

**GET /api/config/claude-md?project=:name** — Read a CLAUDE.md file.
- If `project` is `global` or omitted, read `/data/home/CLAUDE.md`
- Otherwise, look up project in gsd-projects.json by name, read `{project.root}/CLAUDE.md`
- If GSD_DATA_URL is set, proxy the request upstream (same pattern as gsd.js line 184-196)
- Return `{ content: string, path: string }` or 404 if file doesn't exist
- Use `fs.readFileSync` with utf8 encoding

**PUT /api/config/claude-md** — Write a CLAUDE.md file.
- Body: `{ project: string, content: string }`
- Same project resolution as GET (global → /data/home/CLAUDE.md, named → {root}/CLAUDE.md)
- If GSD_DATA_URL is set, proxy the PUT upstream
- Validate content is a string and not empty
- Write with `fs.writeFileSync` (utf8)
- Return `{ ok: true, path: string }`

**GET /api/config/project-settings/:project** — Read project settings.
- Use `stmts.getProjectSettings` from db.js
- If no row exists, return defaults: `{ project_key, verbosity: 'normal', telegram_alerts: {} }`
- Parse `telegram_alerts` from JSON string before returning

**PUT /api/config/project-settings/:project** — Upsert project settings.
- Body: `{ verbosity?: string, telegram_alerts?: object }`
- Validate verbosity is one of 'verbose', 'normal', 'quiet' if provided
- JSON.stringify telegram_alerts before storing
- Use `stmts.upsertProjectSettings`
- Return `{ ok: true, settings: {...} }`

**GET /api/config/project-settings** — List all project settings (for the UI to show current state across projects).
- Use `stmts.listProjectSettings`
- Parse telegram_alerts JSON for each row

Register the router in gsd.js or the main server file. Follow the pattern in server/routes/settings.js — check how routes are mounted in the Express app and mount config routes at `/api/config`.


Use `loadConfig()` helper from gsd.js for project lookup. Since gsd.js already has this function, either extract it to a shared module or re-implement the simple pattern (read gsd-projects.json, find by name).

Create server/routes/projects.js. This is the full controller — implement all five endpoints:

**Architecture decisions:**
- Creation pipeline runs async (fire-and-forget after 202 response). The route responds 202 immediately; a background async function runs the pipeline steps, updating creation_state in SQLite and broadcasting WebSocket messages after each step.
- Each pipeline step is a discrete async function that can be called independently for the resume flow.
- PAT key convention: primary PAT is stored as `github_pat`; additional PATs use `github_pat_<label>` keys. The github-pats endpoint lists all keys matching this pattern.
- Use `execFile` (not `exec`) for all shell commands to avoid injection. Shell metacharacters in project names are sanitized by sanitizeName() before reaching shell commands.
- DATA_HOME: use `process.env.DATA_HOME || '/data/home'` as the root for new projects.
- The gsd-projects.json update is synchronous (loadConfig→push→saveConfig) guarded inside a try block.
- Broadcast: import `broadcast` from `../websocket` if exported, else require stateBroadcaster directly. Use `broadcast('project_creation_state', { project: name, step, status, error })` pattern.

**Validation rules (NPC-05 compliance):**
- Project name: required, 1-64 chars, must not be empty after sanitizeName, must not start with a number
- Folder path for import: must be an absolute path, must exist, must not already be registered
- Name collision: check gsd-projects.json before scaffolding; return 409 with plain-English message
- Disk full: catch ENOSPC; return plain-English message
- GitHub API errors: catch gh CLI stderr; return plain-English message (no stack trace)

**Endpoint specifications:**

```
GET  /api/projects/github-pats
  → lists all PAT keys (github_pat and github_pat_*) with their metadata (key name, set: true)
  → response: { pats: [{ key, label, set }] }

GET  /api/projects/import-candidates
  → calls detectUnregisteredFolders(DATA_HOME, registeredNames)
  → response: { candidates: ['/data/home/foo', ...] }

POST /api/projects/create
  body: { name, description?, template: 'blank', visibility: 'private'|'public', pat_key?: 'github_pat' }
  → validates input
  → upserts creation_state row (current_step: 'scaffold', status: 'creating')
  → responds 202 { ok: true, project: sanitizedName }
  → async pipeline runs in background:
      step 'scaffold': scaffoldProject(root, { name, description })
      step 'git_init': execFile('git', ['-C', root, 'init', '--initial-branch=main'])
      step 'github_create': execFile('gh', ['repo', 'create', sanitizedName, '--source', root, '--remote=origin', '--visibility', visibility])
        Note: gh CLI uses the PAT from GH_TOKEN env var; set GH_TOKEN = getSecret(pat_key || 'github_pat') in the child process env
      step 'git_push': execFile('git', ['-C', root, 'add', '.']) + execFile('git', ['-C', root, 'commit', '-m', 'chore: initial commit']) + execFile('git', ['-C', root, 'push', '-u', 'origin', 'main'])
        Note: set GIT_TERMINAL_PROMPT=0 and GIT_ASKPASS=echo to prevent blocking on auth prompts
      step 'gsd_install': execFile('npm', ['install', '-g', 'get-shit-done'], { cwd: root })
        Actually GSD is not an npm package — check how quick task aa09c13 installed GSD. Use the GSD symlink pattern: create .claude/get-shit-done symlink pointing to /data/home/.claude/get-shit-done if it exists, else skip (GSD install is a best-effort step)
      step 'tmux_start': execFile('tmux', ['new-session', '-d', '-s', sanitizedName, '-x', '220', '-y', '50'])
      step 'claude_launch': 
        - execFile('tmux', ['send-keys', '-t', sanitizedName, `cd ${root} && claude`, 'Enter'])
        - wait 8s for Claude to boot (reuse the Phase 46 heuristic: poll tmux pane for prompt-ready marker up to 30s)
        - send: execFile('tmux', ['send-keys', '-t', sanitizedName, '/gsd-new-project', 'Enter'])
    On each step completion: upsert creation_state, broadcast 'project_creation_state' message, update gsd-projects.json when tmux_start completes
    On failure: upsert creation_state with failed_at_step + error_message; broadcast failure state

POST /api/projects/import
  body: { folder, seed?: boolean }
  → validates folder exists, not already registered
  → determines project name from path.basename(folder)
  → registers in gsd-projects.json
  → starts tmux session
  → if seed=true: sends '/gsd-analyse-codebase' to the tmux session after Claude boots

  → reads creation_state for project
  → finds failed_at_step
  → reruns pipeline from that step
  → responds 202 { ok: true, resuming_from: step }
```

**Security: path traversal guard**

const resolvedRoot = path.resolve(DATA_HOME, sanitizedName);
if (!resolvedRoot.startsWith(path.resolve(DATA_HOME) + path.sep)) {
  return res.status(400).json({ error: 'Invalid project path' });

**Security: shell injection guard**
All shell commands use execFile (not exec/shell: true) with explicit argument arrays. Project name is always passed through sanitizeName() before use in any shell argument.

**Error response format (NPC-05):**
```javascript
// Never: res.status(500).json({ error: err.stack })
// Always:
const PLAIN_ERRORS = {
  ENOSPC: 'Not enough disk space to create the project folder.',
  EEXIST: 'A project named {name} already exists — pick a different name.',
};
function toPlainError(err, name) {
  return PLAIN_ERRORS[err.code]?.replace('{name}', name) || 
    `Something went wrong: ${err.message.split('\n')[0]}`;
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /api/projects/create | User-supplied name, description, visibility, pat_key reach shell commands |
| Server → GitHub API (gh CLI) | PAT passed as GH_TOKEN env var to child process |
| Server → Filesystem | Project root creation under DATA_HOME |
| Server → tmux | Session name derived from user input; send-keys sends user-specified content to tmux |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-05 | Injection | execFile args (project name) | mitigate | sanitizeName() whitelist strips all chars except [a-z0-9-]; execFile uses arg arrays (no shell); verified by grep in acceptance criteria |
| T-51-06 | Injection | tmux send-keys (/gsd-new-project) | accept | Message is a hardcoded slash-command literal, not user input; no injection surface |
| T-51-07 | Information Disclosure | GitHub PAT in child process env | mitigate | PAT passed as GH_TOKEN env var (not in CLI args); getSecret() decrypts server-side only; PAT never included in API responses |
| T-51-08 | Elevation of Privilege | Path traversal via project name | mitigate | path.resolve() + startsWith(DATA_HOME) guard before any mkdir; enforced before scaffoldProject call |
| T-51-09 | Spoofing | pat_key parameter (NPC-06) | mitigate | Route validates pat_key must be in the set returned by listSecretKeys(); rejects unknown keys with 400 |
| T-51-10 | Denial of Service | ENOSPC / runaway pipeline | mitigate | ENOSPC caught and returned as plain-English 507; pipeline steps run with execFile timeout (30s per step via AbortSignal or timeout option) |
</threat_model>

# Phase 51 — UI Design Contract

> Visual and interaction contract for "GUI Project Creation + Import" wizard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | None (not shadcn) |
| Styling | Tailwind CSS + CSS variable theme |
| Component library | Custom (reuse existing Card, Dialog, Skeleton, Button patterns) |
| Icon library | lucide-react (existing) |
| Font | Inter (sans), JetBrains Mono / Fira Code (mono) |
| Dark mode | CSS class strategy via `next-themes` |

**Notes:**
- No shadcn/ui initialization required. Dashboard uses a custom Tailwind + CSS variable system (surface-0 through surface-5, accent indigo #6366f1).
- Reuse existing component patterns: Dialog/Modal overlay (matching `CostDialog.tsx`), Card primitives with `.card-hover` states, Button classes (`.btn-primary`, `.btn-ghost`).
- All new UI surfaces (wizard modal, skeleton card states, progress chips) extend existing surface color tokens and maintain light/dark theme consistency via `index.css`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact form input padding, label spacing |
| md | 16px | Default form field spacing, dialog padding |
| lg | 24px | Section breaks within modal |
| xl | 32px | Dialog max-width padding |
| 2xl | 48px | Major modal/dialog spacing |

Exceptions: None. All measurements align with existing Tailwind utilities (p-4, p-8, p-6, etc.).

**Implementation:** Use Tailwind classes exclusively. Example: `<div className="p-6 gap-4">` for dialog padding and form field spacing.

| Action | Copy | Context |
|--------|------|---------|

| Open import | `Import existing` | Link or split-button below "New Project" |
| Submit creation form | `Create` or `Create Project` | Bottom of modal, enabled only when Name is valid |
| Submit import form | `Import` or `Import & analyze` | Bottom of import modal |

### Wizard: New Project Form Fields

| Field | Label | Placeholder | Help Text |
|-------|-------|-------------|-----------|
| Project name | `Name` | `my-project` | Optional: "Lowercase, dashes, no spaces" |
| Description | `Description` | `What does this do?` | Optional: "Shows in the project card" |
| Template | `Template` | — | `Blank (only option in v5.0)` with radio or dropdown |
| Visibility | `GitHub visibility` | — | Radio buttons: `Private` (default), `Public` |

### Wizard: Import Form

| Field | Label | Content | Help Text |
|-------|-------|---------|-----------|
| Folder picker | `Folder` | Dropdown or text input | Dropdown auto-populated with unregistered folders; text input for custom paths |
| — | — | `Or enter a custom path` | Small label under dropdown for manual input |
| Seeding prompt | (modal dialog) | `"This folder isn't a GSD project yet — seed .planning/ by running /gsd-analyse-codebase?"` | [Confirm / Cancel] buttons |

### States During Pipeline

| State | Copy | Duration |
|-------|------|----------|
| Creating (modal closes) | (skeleton card appears with) | Immediate |
| Progress chip 1 | `Creating repo` | ~1-2s |
| Progress chip 2 | `Pushing to GitHub` | ~2-3s |
| Progress chip 3 | `Starting tmux` | ~2s |
| Progress chip 4 | `Launching Claude` | Variable, 1-5s |
| Success | (card transitions to `working` state) | Continuous |

### Empty States & Errors

| Scenario | Copy | Action |
|----------|------|--------|
| No GitHub PAT configured | `Add a GitHub PAT to enable project creation` | Inline hint; "New Project" button opens Services credentials panel instead |
| Name collision | `A project named {name} already exists — pick a different name or [open the existing one]` | Inline error below Name field; link to existing card |
| Tmux session collision | `A tmux session named {name} is already running. [Open existing session / use a different name]` | Inline error; split suggestion with link |
| Generic creation failure | `Something went wrong at {step}: {plain-English reason}. [Resume / Cancel]` | Card shows `Setup incomplete`; Resume button reruns from last failed step |
| GitHub API error | `Couldn't create the GitHub repo: {reason}. Check your GitHub PAT and try again.` | Card error state; no stack trace |
| Disk full | `Not enough disk space to create the project folder.` | Card error state |
| GSD install failure | `Couldn't install GSD in the new project. Check the terminal for details.` | Card error state; link to tmux session if available |

### Destructive Actions

| Action | Confirmation | Location |
|--------|---------------|----------|
| Cancel mid-creation | `Are you sure? This will delete the partial project folder and GitHub repo.` | Dialog; "Cancel" button in wizard before submit |
| Resume after failure, then cancel | `Stop the setup and keep {partial-state}?` | Card's "Resume" button context; inline confirmation |
| Abort import (seeding step) | Dialog dismisses, import reverts — no confirmation needed | Import dialog seeding prompt [Cancel] |

## Interaction Patterns

### Wizard Workflow

1. **Open**: Click "+ New Project" → modal opens, Name field focused
2. **Fill form**: Tab through Name → Description → Template → Visibility (all optional except Name)
3. **Submit**: Click "Create" (disabled until Name is valid)
4. **Modal closes immediately** → skeleton card appears in projects list with `creating` state
5. **Progress** → chips update in-real-time via Phase 43 state broadcaster (no polling)
6. **Success** → card transitions to `working` state when tmux session is live + `/gsd-new-project` sent
7. **Failure** → card shows `Setup incomplete — failed at {step}` with "Resume" button

### Import Workflow

1. **Open**: Click "Import existing" → modal opens
2. **Select folder**: Dropdown pre-populated with unregistered folders (async on dialog open)
3. **Optional**: Switch to custom path input, type path manually
4. **Submit**: Click "Import"
5. **If `.planning/` missing**: Seeding confirmation dialog → [Confirm / Cancel]
6. **Card appears** with `analyzing` state (if seeding), transitions to `working` on completion
7. **Failure**: Card shows error with plain-English reason

### PAT Pre-Flight Gate

1. **Click "+ New Project"** when zero PATs configured
2. **Modal doesn't open** → instead, Services credentials panel opens with inline hint: "Add a GitHub PAT to enable project creation"
3. **User adds PAT**, panel closes automatically
4. **Click "+ New Project" again** → wizard opens normally

### Resume After Failure

1. **Card shows** `Setup incomplete — failed at {step} (e.g., "Pushing to GitHub")`
2. **Click "Resume"** → pipeline reruns from that step
3. **Progress chips** replay from the failed step onward
4. **Success**: transitions to `working`; failure: shows new error

## Perceived Performance

**Critical path: Wizard submit → card appears working = <5s (NPC-03).**

| Step | Max Duration | Feedback |
|------|--------------|----------|
| Modal open | <100ms | Instant, no skeleton |
| Form validation | <50ms | Inline errors appear immediately |
| Submit → card appears | <200ms | Skeleton card pops into list with "Creating repo" chip |
| Repo creation | 1-2s | Chip updates via state broadcaster |
| Push to GitHub | 2-3s | Chip updates |
| Tmux startup | 2s | Chip updates |
| Claude launch | 1-5s | Chip updates + spinner on current step |
| Card transitions to working | <200ms | Card refreshes from state broadcaster, shows terminal inline |

**No spinners in modal.** Form submit is fire-and-forget; user sees instant skeleton card feedback (spinners block interaction and violate the perceived performance rule).

**Folder dropdown in import modal:** Async fetch of unregistered folders on dialog open, cached in React state. Dropdown shows loading skeleton if fetch is slow (>200ms).

## Accessibility

- **Form labels** paired with inputs via `<label htmlFor="name">` + `id="name"`
- **Required indicator** shown as `*` (not aria-required alone); semantics via `required` attribute on input
- **Focus management**: Modal opens with Name field focused; Tab traverses form in order (Name → Description → Template → Visibility → buttons)
- **Keyboard submit**: Enter key submits the form when no textarea is focused
- **Error messages** linked to inputs via `aria-describedby="name-error"`
- **Modals** have `role="dialog"`, `aria-labelledby` pointing to title, escape key closes (no data loss on cancel, or explicit confirmation)
- **Progress chips** have `aria-current="step"` on the active chip, `aria-label="Creating repo, step 1 of 4"`

## Responsive Behavior

| Breakpoint | Wizard Width | Notes |
|------------|--------------|-------|
| Mobile (< 640px) | 90vw, max 95% viewport | Full-height modal, no scroll container fallback needed (form is short) |
| Tablet (640px - 1024px) | 480px or 90vw (whichever smaller) | Fixed width preferred; fallback to responsive if viewport narrows |
| Desktop (> 1024px) | 480px fixed | Centered, fixed width |

**Modal backdrop** uses `fixed` positioning, fills viewport, dark overlay (`bg-black/50` or `bg-surface-0/80`).

**Form fields** stack vertically at all breakpoints. No multi-column layout (simplicity > density).

## Copywriting Tone

- **Concise, present tense, active voice.** "Creating repo" not "Repo is being created"
- **No jargon.** "GitHub repo" not "remote origin"; "authorization token" not "PAT"
- **No apologies or false cheer.** "Check your network" not "Oops! Uh oh!"; no emojis
- **Plain-English error context.** "Couldn't push to GitHub: {actual error reason}" not stack traces
- **Links are action-oriented.** "[Resume]" button not "[Retry]"; "[open the existing one]" for collision handling

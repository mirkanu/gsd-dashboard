## Copywriting Contract

### Locked Vocabulary (non-negotiable)

| Expert | Novice | Context |
|--------|--------|---------|
| Phase | Step | Planning terminology |
| Plan | Task | Work item inside a step |
| Milestone | Version | Release/delivery milestone |
| `/gsd:*` or `/gsd-*` | {hidden in novice} | Slash commands entirely absent from novice UI |

### Primary UI Copy

| Element | Copy | Context |
|---------|------|---------|
| Top-bar toggle label (left) | "Novice" | Segmented switch left segment |
| Top-bar toggle label (right) | "Expert" | Segmented switch right segment |
| Settings page default tab (novice mode) | "First-run" | Onboarding-focused tab |
| Settings page default tab (expert mode) | "System" | Technical config tab |
| First-run tab heading | "Welcome to GSD Dashboard" (novice mode) | Introductory copy |
| System tab heading | "Advanced Configuration" (expert mode) | Technical copy |
| Toggle feedback toast (success) | "Switched to {mode} mode" | Optimistic update success |
| Toggle feedback toast (failure) | "Failed to save preference. Try again." | Fallback to previous mode + toast |

### Empty-State Copy (novice mode example)

When no projects exist:
- **Heading:** "No Steps started yet"
- **Body:** "Create your first Step to get started. A Step is a unit of work — like 'build a login page' or 'fix the mobile view'."
- **CTA:** "Create Step" (in expert mode: "Create Phase")

### Error-State Copy

**Translation layer missing key (DEV only):**
- Console warning: `console.warn("Missing copy key: {key}")` with key path logged
- Rendered fallback: Return the literal key (e.g., `nav.phase` displays as `nav.phase`) so executor notices and reports

**Translation layer missing key (PROD):**
- Silent fallback: Return the expert key value or key literal, no console output

**UI-mode toggle failure:**
- Visible toast: "Failed to save preference. Try again." + revert UI to previous state immediately

### Destructive Actions (in scope for Phase 50)

None in this phase — all destructive actions (delete project, archive plan) are verbatim from expert mode in novice mode. Phase 56B extends non-programmer behavioural contract.

## Component Specifications

### 1. Top-Bar Mode Toggle

**Location:** `client/src/components/Layout.tsx` — right side of top bar, adjacent to existing controls

**Visual:**
- **Type:** Segmented switch (two segments: "Novice" | "Expert")
- **Size:** 40-44px height (touch-friendly minimum)
- **Width:** ~140px (accommodate both labels + padding)
- **Styling:** Tailwind + CSS vars
  - Inactive segment: `bg-surface-2 text-gray-400`
  - Active segment: `bg-accent-default text-white`
  - Border: 1px `border-border`
  - Border-radius: `rounded-lg`
  - Font size: 13px semibold (label role)
  - Padding: 4px between segments (xs spacing)

**Behavior:**
- **Display:** Always visible, never hidden or moved to menu
- **Initial state:** Reads from `app_settings.ui_mode` (persisted in `GET /api/app-settings`)
- **Interaction flow:**
  1. User clicks target segment
  2. **Optimistic:** Flip UI to new mode immediately (dispatch to React context)
  3. **Network:** `PATCH /api/app-settings` with `{ ui_mode: 'novice' | 'expert' }`
  4. **Success:** UI stays flipped, light toast "Switched to {mode} mode" (2s, auto-dismiss)
  5. **Failure (500, timeout, network error):**
     - Revert UI back to previous mode instantly
     - Show error toast: "Failed to save preference. Try again." (persist until dismissed)
     - Server-side rollback not needed (no writes on failure)
- **Accessibility:**
  - `role="group"` on container
  - Each segment is a `<button>` with `aria-pressed={isActive}`
  - Keyboard: Tab to group, Arrow Left/Right to switch, Enter/Space to confirm

**Interactions (perceived performance rules):**
- Flip is instantaneous (CSS class change + React re-render <16ms)
- Toast appears within 1 frame of network call initiating
- Revert on failure is immediate (<16ms)

### 2. Settings Page Tabs

**Location:** `client/src/components/pages/Settings.tsx` — replace single-section layout with Tabs

**Tab Structure:**

**First-run Tab** (default when `ui_mode=novice`):
- **Heading:** "Welcome to GSD Dashboard"
- **Content sections:**
  1. **Mode Mirror** — Read-only display of current mode + segmented toggle (same as top-bar, always available)
  2. **Quick Start Guide** — Links/cards explaining:
     - "What is a Step?" (corresponds to Phase in expert language)
     - "What is a Task?" (corresponds to Plan)
     - "What is a Version?" (corresponds to Milestone)
  3. **Placeholder for onboarding** — Future phase (Phase 51 project creation) will fill this
- **Styling:** Lighter tone, more descriptive text, larger icons

**System Tab** (default when `ui_mode=expert`):
- **Heading:** "Advanced Configuration"
- **Content sections:**
  - All existing Settings content (pricing editor, idle detector config, advanced toggles, etc.)
- **Styling:** Dense, technical, assumes familiarity with Dashboard concepts

**Tab Control (shadcn pattern, custom implementation):**
- Use shadcn `Tabs` component if available; otherwise implement custom tab control
- **Styling:** Underline style (active tab has bottom border in accent color)
- **Keyboard:** Arrow Left/Right to switch tabs, Tab to enter content
- **ARIA:** `role="tablist"` on container, `role="tab"` on each segment, `aria-selected`, `aria-controls`

### 3. Copywriting Translation Layer

**File:** `client/src/lib/copywriting.ts`

**Public API:**

```typescript
// Pure function, reads mode from module state
export function t(key: string, fallback?: string): string

// React hook for components — returns bound t() tied to current ui_mode
export function useT(): typeof t

// Called by settings provider when mode changes
export function setUiMode(mode: 'novice' | 'expert'): void

// Optional: get current mode
export function getUiMode(): 'novice' | 'expert'
```

**Dictionary Structure:**

```typescript
const copy = {
  novice: {
    nav: {
      gsd: "GSD Dashboard",
      steps: "Steps",
      tasks: "Tasks", // singular "Task" if needed for context
      versions: "Versions",
      // ... nav labels in novice language
    },
    button: {
      runPlan: "Run this Task",
      createPhase: "Create Step",
      // ... button labels
    },
    toast: {
      executed: "Task completed!",
      // ... toast messages
    },
    // ... other domains
  },
  expert: {
    nav: {
      gsd: "GSD Dashboard",
      steps: "Phases",
      tasks: "Plans",
      versions: "Milestones",
      // ... expert language
    },
    // ... mirror structure
  }
}
```

**Key Naming Convention:**
- Dotted notation: `domain.subject` (e.g., `nav.phase`, `button.runPlan`)
- Lowercase camelCase per segment
- No leading verbs (keys are nouns/subjects, not imperatives)

**Missing-Key Behavior:**

| Mode | Key present | Missing in mode | Fallback |
|------|-------------|-----------------|----------|
| novice | ✓ | — | Return novice value |
| novice | ✗ | expert | Return expert value |
| novice | ✗ | both | DEV: console.warn + return key literal (`nav.phase`) |
| novice | ✗ | both | PROD: Return key literal silently |
| expert | ✓ | — | Return expert value |
| expert | ✗ | novice | Return novice value (backward fallback) |
| expert | ✗ | both | DEV: console.warn + return key literal |
| expert | ✗ | both | PROD: Return key literal silently |

**Coverage Scope (must use `t()`):**

✓ **In scope:**
- JSX text children that are string literals
- `title`, `aria-label`, `aria-description`, `placeholder`, `alt` string-literal props
- Toast/sonner message bodies and titles
- Page `<title>` and document headings (`<h1>`, `<h2>`, etc.)
- Empty-state and error copy authored by Dashboard team
- Page headings, section headings, tab labels, button labels, sidebar labels

✗ **Out of scope (bypass `t()`):**
- Dynamic data from API/DB (project names, file paths, log lines, command output, server error messages)
- Strings inside `<code>`, `<pre>`, terminal panes, log viewers
- Numeric formats, dates, ISO timestamps
- Third-party component internals (radix-ui, chatscope internals)
- Comments and variable names in source code (not user-facing)

**Allowlist File:** `client/src/lib/copywriting-allowlist.ts`
- Lists any genuinely-not-translatable string literals (e.g., protocol names, API endpoints, file paths in UI)
- Each entry has a written reason (e.g., "JetBrains Mono is a registered trademark, not translatable")
- AST lint (D-05) skips keys in allowlist

### 4. Test Coverage (Enforcement)

**AST Lint Test** (`npm run test:client:i18n`):
- Walks every `client/src/**/*.{ts,tsx}` (excludes `__tests__/`, `*.test.tsx`, generated)
- Parses JSX and flags string literals in scope D-04 not wrapped in `t(...)` and not in allowlist
- Fails run on any new violation

**DOM Smoke Scan Test** (runs as part of `npm run test:client`):
- Renders each top-level page under `ui_mode=novice` with mocked data
- Asserts rendered text contains NONE of:
  - `/\bphase\b/i` (word boundary match, case-insensitive)
  - `/\bplan\b/i`
  - `/\bmilestone\b/i`
  - `/\/gsd[:-]\w+/` (covers `/gsd:*` and `/gsd-*`)
- Failure blocks `npm run test:client`

## Migration Path (Expert Mode Preservation)

**D-07 Snapshot Tests:**
- Capture current rendered output of each top-level page **before** `t()` migration
- Post-migration, assert expert-mode output matches snapshot pixel-perfect
- Expert mode is verbatim current UI — zero regressions

- Missing keys render as the literal key (e.g., `nav.phase`)
- This is **visible to executor** — they notice it in testing and report it
- Prevention: Dictionary seeding pulls from AST scan pre-migration

## Interaction Sequences

### Sequence 1: User switches to Novice Mode (first-time)

```
1. User clicks "Novice" segment in top-bar toggle
2. Layout.tsx dispatches setUiMode('novice') → copywriting.ts
3. React re-renders with t() calls now routing to novice branch
4. PATCH /api/app-settings initiated (async, non-blocking)
5. UI shows toast "Switched to novice mode" (temporary)
6. Server persists ui_mode='novice' to app_settings
7. Page refresh/reload reads ui_mode='novice' from GET /api/app-settings
8. Novice UI persists across sessions
```

### Sequence 2: User switches mode, network fails

```
1. User clicks "Expert" segment
2. Optimistic flip: UI shows Expert mode immediately
3. PATCH /api/app-settings queued
4. Network times out or 500 error
5. Optimistic revert: UI flips back to Novice immediately
6. Toast appears: "Failed to save preference. Try again."
7. User may retry; localStorage/session state NOT changed
```

### Sequence 3: Settings page tab navigation (Settings.tsx)

```
1. User on Settings page, ui_mode='novice'
2. First-run tab is active by default (shows onboarding + mode toggle)
3. User clicks "System" tab
4. Tab content switches to technical settings (pricing, idle config, etc.)
5. Switching back to "First-run" shows onboarding again
6. Tab preference NOT persisted (resets to default tab on page reload)
```

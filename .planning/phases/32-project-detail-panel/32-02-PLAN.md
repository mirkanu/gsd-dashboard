Actually, re-check the logic: the confirm handler should bypass the guard. Better approach -- use a ref or pass a force flag:

   Revised approach: In handleSend, check `if (isPausedOrArchived && pendingMessage === null)` instead. When handleConfirmSend sets pendingMessage and calls handleSend, the pendingMessage is non-null so it passes through. After sending, clear pendingMessage.

   Simplest correct approach:
   ```typescript
   const handleSend = useCallback(async (text: string, force = false) => {
     const trimmed = text.trim();
     if (!trimmed || sending) return;

     const isPausedOrArchived = sessionState === "paused" || sessionState === "archived";
     if (isPausedOrArchived && !force) {
       setPendingMessage(trimmed);
       setShowReopenConfirm(true);
       return;

     setShowReopenConfirm(false);
     setPendingMessage(null);
     // ... existing optimistic + API send logic
   }, [projectName, sending, sessionState]);

   const handleConfirmSend = useCallback(() => {
     if (pendingMessage) handleSend(pendingMessage, true);
   }, [pendingMessage, handleSend]);
   ```

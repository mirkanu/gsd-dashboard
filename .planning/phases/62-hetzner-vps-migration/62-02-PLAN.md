SSH into VPS. Run the following to create a named Cloudflare Tunnel and configure DNS ingress rules:

```bash
# 1. Authenticate cloudflared with Cloudflare account
# Uses CLOUDFLARE_API_KEY and CLOUDFLARE_EMAIL from /home/services/.env.production
# NOTE: cloudflared login opens a browser — instead use cert.pem approach:
cloudflared tunnel login
# This outputs a cert.pem URL — paste into browser, authorize, cert downloads to ~/.cloudflared/cert.pem

# 2. Create the named tunnel
cloudflared tunnel create gsdlabs-production
# This creates credentials.json in ~/.cloudflared/{TUNNEL_ID}.json
# Output: "Created tunnel gsdlabs-production with id {TUNNEL_ID}"
# Note the TUNNEL_ID for DNS route commands below

# 3. Create config directory and move credentials
mkdir -p /root/.cloudflare-tunnel
cp ~/.cloudflared/{TUNNEL_ID}.json /root/.cloudflare-tunnel/credentials.json
chmod 600 /root/.cloudflare-tunnel/credentials.json

# 4. Write the tunnel config file
cat > /root/.cloudflare-tunnel/config.yml << 'CFEOF'
tunnel: gsdlabs-production
credentials-file: /root/.cloudflare-tunnel/credentials.json
metrics: localhost:8000
no-autoupdate: true

ingress:
  - hostname: dashboard.gsdlabs.dev
    service: http://localhost:4820
  - hostname: debates.gsdlabs.dev
    service: http://localhost:3000
  - hostname: ynab.gsdlabs.dev
    service: http://localhost:3001
  - hostname: kidai.gsdlabs.dev
    service: http://localhost:3002
  - hostname: api.gsdlabs.dev
    service: http://localhost:5000
  - service: http_status:404
CFEOF
chmod 600 /root/.cloudflare-tunnel/config.yml

# 5. Add DNS CNAME routes for each subdomain (Cloudflare creates CNAME records pointing to tunnel)
cloudflared tunnel route dns gsdlabs-production dashboard.gsdlabs.dev
cloudflared tunnel route dns gsdlabs-production debates.gsdlabs.dev
cloudflared tunnel route dns gsdlabs-production ynab.gsdlabs.dev
cloudflared tunnel route dns gsdlabs-production kidai.gsdlabs.dev
cloudflared tunnel route dns gsdlabs-production api.gsdlabs.dev

# 6. Test the tunnel config is valid
cloudflared tunnel --config /root/.cloudflare-tunnel/config.yml ingress validate
# Must output: "OK" for each ingress rule

# 7. Start the tunnel via PM2 (replaces quick tunnel gsd-tunnel)
# First, stop the existing gsd-tunnel if migrating from quick tunnels on THIS VPS
# (Not needed on VPS — only the local SSH host runs gsd-tunnel currently)

# Create PM2 start command for named tunnel on VPS
pm2 start "cloudflared tunnel --config /root/.cloudflare-tunnel/config.yml run" \
  --name gsd-tunnel \
  --log /root/.pm2/logs/gsd-tunnel.log \
  --restart-delay 5000

pm2 save

# 8. Enable PM2 startup on VPS reboot
pm2 startup
# Run the command it outputs (will be something like: systemctl enable pm2-root)
```

Note: `cloudflared tunnel login` may require a browser interaction. If running headlessly over SSH,
use the alternative cert-based approach:
- Run `cloudflared tunnel login` on VPS
- Copy the URL it prints to stdout
- Open that URL on local browser, authorize
- cloudflared will detect the authorization and write ~/.cloudflared/cert.pem automatically

Replace the existing Railway CLI deploy workflow with the SSH-to-VPS pattern from RESEARCH.md Pattern 1.
The existing workflow triggers on push to `master` — keep that trigger.

Write the new deploy.yml:

```yaml
name: Deploy to Hetzner VPS

on:
  push:
    branches:
      - master
  workflow_dispatch:  # Manual trigger for re-deploys

env:
  SERVICE_NAME: gsd-dashboard
  SERVICE_PATH: /home/services/gsddashboard

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Deploy via SSH to Hetzner VPS
        uses: appleboy/ssh-action@v1.0.0
        with:
          host: ${{ secrets.HETZNER_VPS_IP }}
          username: root
          key: ${{ secrets.HETZNER_SSH_KEY }}
          port: 22
          script: |
            set -eux

            cd ${{ env.SERVICE_PATH }}

            git fetch origin master
            git checkout origin/master

            # Rebuild and restart only the gsd-dashboard service
            # (runs via PM2, not Docker Compose — per D-01)
            npm ci --production
            pm2 restart gsd-dashboard || pm2 start npm --name gsd-dashboard -- start

            # Verify service is healthy
            sleep 5
            curl -f http://localhost:4820/api/health || exit 1

            echo "Deployment successful"
```

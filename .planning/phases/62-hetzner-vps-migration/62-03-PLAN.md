- Reforma is entirely on Vercel (frontend) + Railway PostgreSQL (database only)
- No server component runs on Railway for reforma — just a managed PostgreSQL with pgvector
- Source DATABASE_URL is in /data/home/reforma/.env (format: postgresql://postgres:{password}@shinkansen.proxy.rlwy.net:34275/railway)
- The database uses pgvector extension for 1536-dim embeddings (text-embedding-3-large)

- After migration, Vercel environment variable DATABASE_URL must be updated to the new VPS connection string
- VPS PostgreSQL port 5432 must be reachable from Vercel (the VPS firewall currently allows only port 22)
  → IMPORTANT: Port 5432 must be opened in ufw for Vercel's outbound IPs OR we expose postgres on a non-standard port

NOTE on firewall: Railway PostgreSQL is exposed on proxy port 34275 (non-standard). For the VPS,
we expose PostgreSQL on port 5432 but restrict access with ufw to known CIDRs. Since Vercel's
outbound IPs are not fixed, we must allow 0.0.0.0/0 on 5432 but use a strong POSTGRES_PASSWORD.
A better alternative: use a pg_bouncer or Cloudflare Tunnel for DB connections — but that is out
of scope. Accept the tradeoff: strong password (from .env.production) + no plaintext in URLs.

Step 1 — Add reforma-db to docker-compose.yml on the VPS.

SSH into VPS and update /home/services/hetzner-vps/docker-compose.yml.
Add the reforma-db service block inside the `services:` section:

```yaml
  reforma-db:
    image: pgvector/pgvector:pg16
    container_name: reforma-db
    environment:
      POSTGRES_DB: reforma
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - reforma-db-data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
```

Start the container:
```bash
cd /home/services/hetzner-vps
docker compose --env-file /home/services/.env.production up -d reforma-db
# Wait for health check to pass
docker compose --env-file /home/services/.env.production ps reforma-db
# Status must show "healthy" (may take 15-30s)
```

Step 3 — Dump Railway reforma database from this local machine.
The source DATABASE_URL is in /data/home/reforma/.env:
```bash
# Run on THIS machine (claude-code-ssh host), not on VPS
source /data/home/reforma/.env  # loads DATABASE_URL
pg_dump "$DATABASE_URL" -Fc -f /tmp/reforma-railway-dump.dump
ls -lh /tmp/reforma-railway-dump.dump
```

Step 4 — Copy dump to VPS and restore into the container:
```bash
# Copy dump from this machine to VPS
scp /tmp/reforma-railway-dump.dump root@{VPS_IP}:/tmp/reforma-railway-dump.dump

# SSH to VPS and restore
ssh root@{VPS_IP} << 'RESTORE_EOF'
# Restore into reforma-db container using pg_restore
docker exec -i reforma-db pg_restore \
  -U postgres \
  -d reforma \
  --no-owner \
  --no-acl \
  --exit-on-error \
  /tmp/reforma-railway-dump.dump || \
docker exec -i reforma-db psql -U postgres -d reforma -c "SELECT 1" # verify DB exists

# Verify pgvector extension is present
docker exec reforma-db psql -U postgres -d reforma \
  -c "SELECT extname, extversion FROM pg_extension WHERE extname='vector';"

# Clean up dump file on VPS
rm -f /tmp/reforma-railway-dump.dump
RESTORE_EOF

# Clean up dump on local machine
rm -f /tmp/reforma-railway-dump.dump
```

| Local machine → Railway pg_dump | pg_dump reads from Railway using DATABASE_URL; dump file is plaintext on disk during transfer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-11 | Disclosure | pg_dump file in /tmp during transfer | mitigate | Delete dump file immediately after restore (both machines); dump is compressed Fc format (not plaintext SQL) |
| T-62-12 | Disclosure | PostgreSQL port 5432 exposed on VPS | accept | VPS PostgreSQL uses POSTGRES_PASSWORD (32-char random from openssl); no public schema exposed; acceptable tradeoff vs. Vercel fixed IP restriction complexity |
| T-62-13 | Tampering | Wrong row count after restore | mitigate | Explicit row count comparison between Railway source and VPS destination before declaring success |
| T-62-14 | Disclosure | Old Railway DATABASE_URL still in .env after migration | mitigate | Update .env to use new URL; old URL kept as comment only (Railway service deleted in Plan 10 removes credential validity) |

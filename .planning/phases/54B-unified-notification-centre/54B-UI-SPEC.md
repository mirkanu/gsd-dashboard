# Phase 54B — UI Design Contract

> Visual and interaction contract for unified notification centre frontend. Refactors existing Telegram alert toggles (Phase 42, Config page) into a full notification governance centre with event policy, quiet hours, and rate limiting. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | HTML + Tailwind CSS |
| Icon library | lucide-react (existing) |
| Font | Inter (sans), JetBrains Mono (code) |

## Layout & Component Inventory

### Notification Centre Settings Panel (in ConfigPage)

**Location:** ConfigPage.tsx, new `Notifications` tab alongside existing `Verbosity` and `Telegram Alerts` sections.

**Layout: Vertical stack, 1-column**

1. **Header: Global Enable/Disable**
   - Toggle: "Notifications" (16px label + 20px toggle)
   - Subtext: "Receive filtered Telegram messages for selected events" (12px gray-400)
   - Spacing: 16px below header

2. **Quiet Hours Section**
   - Label: "Quiet Hours" (14px semibold)
   - Two time inputs: "From" and "To" (24px gap between)
   - Input styling: `.input` class (bg-surface-2, border-border, accent focus)
   - Helper text: "No notifications outside [from] and [to] except high-priority" (12px gray-500)
   - Spacing: 16px above, 16px below

3. **Rate Limit Section**
   - Label: "Rate Limit" (14px semibold)
   - Dropdown/Number input: "Max N notifications per hour" (default 5)
   - Helper: "Excess events deduplicated or queued for later delivery" (12px gray-500)
   - Spacing: 16px above, 16px below

4. **Event Type Toggles (Vertical List)**
   - For each event type (see NTF-02 + default policy table below):
     - Checkbox + Label on same row, 8px gap
     - 12px small text beneath with event description
     - Spacing: 12px between rows
   - Event types:
     - ☑ Session waiting for user input
     - ☑ Plan/phase completed
     - ☑ Verify-work failed (high priority)
     - ☐ Verify-work passed (after retry)
     - ☑ Idle session auto-closed (Phase 48)
     - ☑ External service cost anomaly
     - ☐ New external GitHub Issue filed (Launched only)
     - ☐ Session started
     - ☐ Individual tool-use events
     - ☐ Claude finished responding (per turn)

5. **Per-Project Overrides (Table)**
   - Column 1: Project name
   - Column 2: Notification toggle (per project)
   - Column 3: Custom quiet hours override (dropdown: "Use global" / "Custom")
   - Spacing: 8px between rows
   - Only show projects in "launched" or higher stage (from Phase 58)

6. **Action Buttons (Row)**
   - Left: "Test Telegram" (secondary/ghost button)
   - Right: "Save Settings" (primary button)
   - Spacing: 16px gap, 16px from panel bottom

### Notification History Panel (Optional, Phase 54B Wave 2)

**Location:** New "Notifications" page in sidebar (alongside FeedPage from Phase 56).

**Layout: List + detail pane**

1. **Recent Notifications List**

## State & Behavior

### Notification Toggle States

1. **Disabled (all)**
   - All event toggles grayed out (opacity-50)
   - Quiet Hours inputs disabled
   - Rate Limit input disabled
   - Text: "Enable notifications to configure events"

2. **Enabled (all)**
   - All toggles active + interactive
   - Quiet Hours + Rate Limit active
   - Save button enabled on any change

3. **Quiet Hours Active**
   - Banner at panel top: "Currently in quiet hours (until 7:00 AM)"
   - Only high-priority events (verify-work failed, cost anomaly) allowed
   - Other events queue for delivery at resume time

4. **Rate Limit Threshold Exceeded**
   - Visual indicator: "📊 Rate limit: 5/5 used in this hour"
   - Excess events: deduplicate (show "2 more…" link) or queue
   - Counter resets at top of hour

### Telegram Delivery States

- **Pending:** (no visual, happens silently)
- **Sent:** Notification removed from "needs delivery" queue
- **Failed:** Retry badge + timestamp of last attempt
- **Deferred:** "Queued until [time]" state in history view

## Event Policy Table (NTF-02 + ROADMAP default policy)

Default behaviour when notifications enabled:

| Event | Enabled | Rationale | Rate Limited |
|-------|---------|-----------|-------------|
| Session waiting for user input | Yes | The thing you actually need to know | No (high priority) |
| Plan/phase completed | Yes | Portfolio-level milestone | No (high priority) |
| Verify-work failed | Yes | Requires a decision | No (high priority) |
| Verify-work passed (after retry) | No | Success is expected | — |
| Idle session auto-closed (Phase 48) | Yes | Cost-relevant | Yes |
| External service cost anomaly | Yes | Cost-relevant | Yes |
| New external GitHub Issue filed (Launched only) | No | Launched-stage projects only | — |
| Session started | No | You started it | — |
| Individual tool-use events | No (permanent) | Current noise source | — |
| Claude finished responding (per turn) | No | Intra-session | — |

## Accessibility & Mobile

- All toggles: `role="switch"` with `aria-checked`
- Time inputs: `type="time"` HTML5 (respects device locale)
- Number inputs: `type="number"` with min/max, keyboard-friendly
- Quiet hours: UTC offset clarification in help text (not automatic)
- Rate limit: accessible counter display (not just a visual gauge)
- **Mobile:** Vertical layout adapts to 320px width; toggles full-width; time inputs use native picker

## Notes for Executor

1. **ConfigPage extension:** Add new Notifications tab/section. Reuse existing `.input`, `.toggle`, and `.card` classes from index.css.

2. **Settings API contract:** 
   - New schema field: `notification_policy` (JSON structure with enabled, quiet_hours_from, quiet_hours_to, rate_limit_per_hour, event_toggles object)
   - GET /api/app-settings returns this alongside existing fields
   - PUT /api/app-settings accepts and validates notification_policy (no nulls in toggle keys, time format HH:MM, rate limit 1–100)

3. **Per-project overrides:** Stored in `project_settings` table (existing structure from Phase 51). Render in Notifications section only if project is launched/maintenance (MAT-02 scope gating).

4. **Color semantic:** Use existing accent (#6366f1) for enabled toggles. Reference blue-500 and red-500 from Tailwind defaults (no new tokens needed).

5. **No new routes required in UI:** Extend ConfigPage, no new page. Phase 54B focuses on settings UI; Phase 54B Wave 2 may add NotificationHistoryPage for recent delivery log.

6. **Test Telegram button:** Call `/api/test-telegram` (new backend route in Phase 54B executor) which sends a test message. Show success toast or error toast.

7. **Quiet hours format:** Store as ISO time strings (HH:MM), display in user's local timezone (use `<input type="time">` which auto-localizes).

8. **Migration path for Phase 42 users:** On first load, if old `telegram_alerts` schema detected, run one-time transform to new `notification_policy` schema, set `archived_legacy_alerts: true`, hide the old toggle section.

  <action>
Run all commands as root on the Hetzner VPS:

```bash
# 1. Create docker group if missing (it exists at GID 988 per research — this is a no-op guard)
getent group docker || groupadd docker

# 2. Create claude user with home at /home/claude
useradd -m -s /bin/bash -d /home/claude claude

# 3. Add claude to docker group (GID 988)
usermod -aG docker claude

# 4. Copy SSH authorized_keys using install to get permissions right in one step
install -m 700 -d /home/claude/.ssh
install -m 600 /root/.ssh/authorized_keys /home/claude/.ssh/authorized_keys
chown -R claude:claude /home/claude/.ssh

# 5. Verify
id claude
groups claude
ls -la /home/claude/.ssh/
```

Do NOT add claude to the sudo group — per CONTEXT.md, sudo is not required.

| SSH public key | Copied authorized_keys gives same access as root had; no new keys introduced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-70-01-01 | Elevation of Privilege | sudo group membership | mitigate | Do NOT add claude to sudo group — claude has no sudo access |
| T-70-01-02 | Information Disclosure | authorized_keys copy | accept | Same keys as root; reduces surface by moving to non-root user; root SSH kept for recovery only |
| T-70-01-03 | Tampering | chown -R on /home/services | accept | Ownership transfer is intentional; Docker containers run as their internal UIDs independently of host ownership |
</threat_model>

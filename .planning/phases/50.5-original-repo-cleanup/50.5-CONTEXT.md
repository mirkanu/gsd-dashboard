# Phase 50.5: Original-Repo Cleanup — Context

**Gathered:** 2026-04-18
**Status:** Ready for planning
**Source:** Authoritative milestone spec (v5.0 ROADMAP.md + REQUIREMENTS.md CLN-01..CLN-06)

<domain>
## Phase Boundary

**Problem:** The GSD Dashboard was forked from `hoangsonww/Claude-Code-Agent-Monitor`. Several features and files from that upstream fork are now dormant or mis-fit for the v5.0 direction. Leaving them in place:
- Adds cognitive load (routes/views nobody uses)
- Adds attack surface + dependency bloat (unused SQL tables, scripts, workflows)
- Causes confusion for new-programmer users (CLN-01 legacy Sessions/ActivityFeed views don't match the project-centric mental model of v5.0)
- Blocks Phase 54B (Unified Notification Centre) by keeping `useNotifications` browser-notification infra around to confuse the integration

**Deliverable:** Targeted removal + reorganization of upstream-inherited code. Mostly deletion. One rewrite (`install-hooks.js`) and two route modifications (`/api/settings/export` rewrite, `/api/settings/cleanup` removal).

**Non-goals:**
- No new features
- No behaviour changes to code that stays (stateBroadcaster, idleDetector, busyMarkers, routes/gsd.js, ServicesPage, UsagePage, ConfigPage all untouched)
- No refactors beyond what deletion forces (e.g. removing an import chain that's now empty)
- No renames beyond `KanbanBoard.tsx` → `client/src/components/board/KanbanBoard.tsx`

</domain>

<decisions>
## Implementation Decisions

### CLN-01 — Remove `/kanban` route + Sessions/SessionDetail/ActivityFeed views
- **Delete files:**
  - `client/src/pages/KanbanBoard.tsx` (to be moved in CLN-02, not kept in place)
  - `client/src/pages/Sessions.tsx`
  - `client/src/pages/SessionDetail.tsx`
  - `client/src/pages/ActivityFeed.tsx`
  - Their test files (if any exist in `client/src/pages/__tests__/`)
- **Remove routes:** edit `client/src/App.tsx` (or wherever `react-router` routes live) to drop `/kanban`, `/sessions`, `/sessions/:id`, `/activity` entries and their nav links
- **Rationale:** Superseded by the project-centric Dashboard view (`GSD.tsx` + `ChatListView.tsx`). The portfolio-level stream comes back in Phase 56 as the Portfolio Feed.

### CLN-02 — Relocate `KanbanBoard.tsx` as generic reusable primitive
- **New location:** `client/src/components/board/KanbanBoard.tsx`
- **Strip:** all agent-specific logic (agent state columns, tool-call rendering, subagent expansion). Keep only: column layout, drag-drop skeleton, card abstraction.
- **Type contract:** export a `<KanbanBoard items columns onMove />` generic where `items` and `columns` are caller-provided.
- **No route references:** no `<Route path="/kanban">` entry anywhere. Parked for Phase 61 (v5.1).
- **Tests:** keep or add a minimal unit test that exercises the generic contract with mock data.

### CLN-03 — Remove `useNotifications` hook + Settings browser-notification toggles
- **Delete files:**
  - `client/src/hooks/useNotifications.ts` (or `.tsx`)
  - Any `BrowserNotificationToggle.tsx` component if it exists as its own file
- **Edit `client/src/pages/Settings.tsx`:** remove the browser-notification section entirely. Leave other Settings sections (theme, idle auto-close, Telegram, etc.) untouched.
- **Rationale:** Phase 54B will deliver unified notifications via server-side Telegram; browser notifications are dead infra that confuses the mental model.

### CLN-04 — Remove import/seed scripts + standalone statusline + startup hook
- **Delete files:**
  - `scripts/seed.js`
  - `scripts/import-history.js`
  - `statusline/` directory in repo root (standalone statusline that was never used by this project)
- **Edit `server/index.js`:** remove any startup-time invocation of `import-history.js` (likely an `if (process.env.IMPORT_ON_START) { require('../scripts/import-history')() }` block or similar). Remove the env var reference too.
- **Rationale:** Seed was for development fixture data; nobody uses it. Import-history was from the fork's session-replay concept we never enabled.

### CLN-05 — Audit + drop unused server routes and SQL tables
- **Investigate first, then delete:**
  - Grep for callers of `server/routes/events.js` endpoints. If zero active callers (not counting tests of the route itself), delete the route + unmount it from `server/index.js` + delete the route's test file.
  - Same for `server/routes/agents.js`.
- **SQL tables to audit:** `agents`, `events`, `token_usage`. For each:
  - Grep for `INSERT INTO {table}`, `SELECT ... FROM {table}`, `UPDATE {table}`, `DELETE FROM {table}` across the whole server + MCP + scripts.
  - If the only inserters are upstream-inherited routes that CLN-05 just deleted, the table is dead — drop it.
- **Schema changes:** if any table is dropped, write a migration step in `server/db.js` or wherever the schema bootstrap lives. Use `DROP TABLE IF EXISTS` for safety.
- **Preserve:** `sessions`, `project_tasks`, `sessions`, `external_service_costs`, `service_mapping_rules`, `manual_cost_entries`, `app_settings`, `autopilot_runs`, `process_registry`, `model_pricing`, `claude_api_usage`, `classifier_feedback`, `classifier_overrides`, `processed_emails`, `project_settings`, `gsd_messages` — all currently in use per earlier session audit.
- **Audit output:** document findings in a short `AUDIT-CLN-05.md` committed alongside the deletion commit (what was checked, what was kept, what was dropped, why).

### CLN-06 — Upstream infra cleanup + `install-hooks.js` rewrite + export/cleanup routes
- **Delete files:**
  - `Dockerfile` if it exists (project deploys via Railway nixpacks/buildpacks, not Docker)
  - `.github/workflows/*.yml` files that are from the upstream and not actively running
- **Audit first:** check `.github/workflows/` for any workflow that matches "this repo's actual CI/CD". If CI workflows are actively used (check recent runs in the GitHub UI or `.github/workflows/` git-log), keep them.
- **Rewrite `scripts/install-hooks.js`:**
  - Today's content: probably installs upstream's hook set (agent-monitoring events, old session hooks).
  - New content: installs the **current** GSD Dashboard hook set:
    - Phase 49 busy markers (`.claude/hooks/gsd-busy-marker.js` + matching entries in `.claude/settings.json` for `PreToolUse`/`PostToolUse`/`SubagentStop`)
    - Existing GSD workflow hooks: `gsd-context-monitor.js`, `gsd-phase-boundary.sh`, `gsd-prompt-guard.js`, `gsd-read-guard.js`, `gsd-session-state.sh`, `gsd-statusline.js`, `gsd-validate-commit.sh`, `gsd-workflow-guard.js`, `gsd-check-update.js`
    - Future-friendly: leave a comment block listing Phase 54B notification event hooks as "added here when shipped"
  - Idempotent: running twice should not duplicate entries in `.claude/settings.json` (merge logic, not append-only).
- **Route changes:**
  - `server/routes/app-settings.js` (or wherever `/api/settings/*` lives): DELETE the `/api/settings/cleanup` route handler (superseded by Phase 48's idle detector which handles tmux cleanup). Delete any test that exercises it.
  - Same route file: REWRITE the `/api/settings/export` handler to cover the current schema (`projects`, `project_tasks`, `app_settings`, `external_service_costs`, `service_mapping_rules`). The output shape is a JSON document with one top-level key per table. Useful for Phase 58 Retired-stage transitions (user wants their data portable when a project is retired).

<specifics>
## Specific Ideas

### Suggested plan breakdown
Planner to validate against anti-shallow rules. Proposal:

- **Plan 50.5-01 — Client route + view deletions (CLN-01, CLN-02, CLN-03)**
  Frontend-only. Deletes Sessions/SessionDetail/ActivityFeed pages, drops `/kanban` route, moves KanbanBoard.tsx, strips browser-notification Settings section. Client tests updated. No server changes.

- **Plan 50.5-02 — Script + statusline cleanup (CLN-04)**
  Mostly filesystem deletion. Edit `server/index.js` to drop the import-history startup hook. Runs `npm run test:server` to confirm server still boots.

- **Plan 50.5-03 — Server route + schema audit (CLN-05)**
  Audit-first plan: grep for callers, produce `AUDIT-CLN-05.md`, then delete dead routes + drop dead tables. Includes a schema bootstrap check. Probably the riskiest plan — preserve transaction boundaries, use `DROP TABLE IF EXISTS`.

- **Plan 50.5-04 — Infra cleanup + install-hooks rewrite + export/cleanup routes (CLN-06)**
  `Dockerfile` + upstream workflows audit+delete. `install-hooks.js` rewrite with idempotent merge into `.claude/settings.json`. `/api/settings/cleanup` removal. `/api/settings/export` rewrite.

Plans are largely independent — can run in Wave 1 in parallel (no file overlap between them, planner to verify).

### Risks
- **Schema drop risks (CLN-05):** dropping a table that turns out to have readers we missed = data loss. Mitigation: `DROP TABLE IF EXISTS` + `AUDIT-CLN-05.md` documenting the grep results + test suite green after drop.
- **`install-hooks.js` idempotency (CLN-06):** naive overwrite would blast user's local `.claude/settings.json` customizations. Mitigation: parse existing JSON, merge new entries, only overwrite fields we manage.
- **Route deletion during active session:** if the dashboard is live when we deploy, a user mid-navigation to `/kanban` would 404. Mitigation: routes just return to Dashboard default; add a brief client-side redirect for the deleted paths pointing to `/` so bookmarks don't die.

### Test strategy
- Full `npm run test:server` + `npm run test:client` after each plan
- `npm run mcp:typecheck` + `npm run mcp:build` (server deletions could ripple to MCP)
- Manual smoke: after deploy, confirm Dashboard loads, no 404s in console, project cards render

</specifics>

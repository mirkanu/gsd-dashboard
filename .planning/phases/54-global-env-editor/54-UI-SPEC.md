## Layout

### Page structure

The Global Env Editor is a new page in the Dashboard sidebar, not a tab on ConfigPage. It follows the established page pattern from ConfigPage.tsx and ServicesPage.tsx.

```
<div class="space-y-6">
  <!-- Header: icon + title + subtitle -->
  <!-- Toolbar: path display + Reload button + Add Row button -->
  <!-- Key=Value table card (primary editor) -->
  <!-- Save bar: sticky at bottom of card (Save Changes button + status indicator) -->
</div>
```

### Key=Value table

Each env entry is a row with three cells:
1. **Key** — monospace input, left-aligned, `w-56` (fixed-width column)
2. **Value** — monospace input, flex-1, shows `••••••••` placeholder when the key matches a known secret pattern (see below)
3. **Actions** — icon-only Delete button (Trash2, 16px, `text-gray-500 hover:text-red-400`)

A header row above the first entry uses label text: "KEY" and "VALUE" in `text-xs text-gray-500 uppercase tracking-wider`.

New rows are appended at the bottom via "Add row" button. Empty key rows are ignored on save.

### Secret masking

Keys whose names contain `_KEY`, `_SECRET`, `_TOKEN`, `_PASSWORD`, `_PAT`, or `_PASS` render the value input as `type="password"`. A toggle icon button (Eye / EyeOff from lucide-react) sits between the value input and the Delete button. Default state: masked. User can toggle per-row.

This is a client-side display courtesy — the server sends and receives plaintext; masking is UI-only.

### Unsaved changes

A pill `"Unsaved changes"` in `text-yellow-400 bg-yellow-500/10` appears in the toolbar when the in-memory state diverges from the last loaded snapshot. Disappears after a successful save.

## States and Interactions

### Loading state
- Skeleton rows (3 rows of `h-8 bg-surface-3 rounded animate-pulse`) in place of the table.
- Toolbar shows "Loading…" in place of path text.

### Loaded state
- File path shown in monospace below the header, e.g. `/home/services/.env.production`.
- Table populated with parsed key=value pairs, one row each.
- Blank lines and comment lines (`# ...`) are preserved as read-only display rows with `text-gray-500 italic` styling (not editable, not deletable, shown verbatim).

### Empty file state
- Table shows no data rows.
- A muted message: "This file is empty. Add your first key below."
- "Add row" button is always visible.

### Error state (load failure)
- Red banner below the toolbar: `AlertCircle` icon + "Could not read /home/services/.env.production — check file permissions."
- No table rendered.
- Retry button: "Try again" (ghost style).

### Error state (save failure)
- Red banner below the Save button: error message from server.
- Unsaved changes pill remains visible.

### Save in progress
- "Save changes" button shows `Loader2 animate-spin` + "Saving…" text, disabled.
- Inputs are not disabled during save (non-blocking).

### Save success
- "Save changes" button briefly shows `Check` icon + "Saved" text in `text-emerald-400`, reverts to normal after 2500ms.
- "Unsaved changes" pill disappears.

### Write permission error (403/EACCES)
- Yellow `AlertTriangle` banner: "Permission denied — the Dashboard server does not have write access to this file."
- Save button is hidden (not disabled) after this error to prevent repeated failed attempts.

| Element | Copy |
|---------|------|
| Page title | "Global Environment" |
| Page subtitle | "View and edit /home/services/.env.production" |
| Primary CTA | "Save changes" |
| Add row button | "Add row" |
| Reload button | "Reload" |
| Empty state heading | "No variables yet" |
| Empty state body | "This file is empty. Add your first key below." |
| Load error | "Could not read the env file — check server file permissions." |
| Save error (generic) | "Save failed: {error message from server}. Your changes are still in the editor." |
| Permission error | "Permission denied — the server process cannot write to this file." |
| Unsaved changes pill | "Unsaved changes" |
| Mask toggle tooltip (masked) | "Show value" |
| Mask toggle tooltip (unmasked) | "Hide value" |
| Delete row tooltip | "Delete row" |
| Save success flash | "Saved" |
| Comment row label | (none — render raw comment text as-is in gray italic) |

Destructive actions:
- **Delete row** — no confirmation dialog. Row is removed instantly from in-memory state. The user must press "Save changes" for it to persist. Because the save is a separate explicit step, the delete action is reversible (Reload discards all unsaved changes).
- **No destructive confirmation modal required.** The two-step edit→save pattern provides the guard. This follows the ConfigPage CLAUDE.md textarea pattern.

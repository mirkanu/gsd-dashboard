**GSD.tsx (ACT-03 unread tracking):**

1. Add state for unread counts near the other useState declarations (~line 782):
```typescript
const [unreadCounts, setUnreadCounts] = useState<Record<string, number>>({});
```

2. Add a ref to track the currently active project (avoids stale closure in eventBus subscription):
```typescript
const activeProjectRef = useRef<string | undefined>();
activeProjectRef.current = chatView.project;
```

3. Add a useEffect that subscribes to eventBus for `gsd_chat_message` events. When a message arrives for a project that is NOT the currently-viewed project, increment that project's unread count. Place this near the existing eventBus subscription (~line 889):
```typescript
useEffect(() => {
  const unsub = eventBus.subscribe((msg) => {
    if (msg.type !== 'gsd_chat_message') return;
    const evt = msg.data as GsdChatMessageEvent;
    if (evt.project === activeProjectRef.current) return;
    setUnreadCounts(prev => ({
      ...prev,
      [evt.project]: (prev[evt.project] || 0) + 1,
    }));
  });
  return unsub;
}, []);
```

4. Import `GsdChatMessageEvent` from `../lib/types` if not already imported.

5. Update ALL places where `onSelectProject` is called (both mobile and desktop paths) to also reset the unread count. There are three locations:
   - Desktop grid ChatListView (~line 1056): `onSelectProject={(name) => { setChatView({ view: 'chat', project: name }); setUnreadCounts(prev => ({ ...prev, [name]: 0 })); }}`
   - Mobile chat list ChatListView (~line 1161): same pattern
   - Any other setChatView calls that set a project should also reset the count

6. Pass `unreadCounts` prop to both ChatListView instances:
   - Desktop: `<ChatListView ... unreadCounts={unreadCounts} />`
   - Mobile: `<ChatListView ... unreadCounts={unreadCounts} />`

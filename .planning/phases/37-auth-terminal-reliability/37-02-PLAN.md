<objective>
Add WebSocket keepalive to the terminal backend and auto-reconnect to the terminal client so
idle terminal sessions stay connected indefinitely and dropped connections self-heal.

Purpose: The terminal WebSocket has no ping/pong heartbeat. Railway's proxy (and any TCP
load balancer) kills idle connections after ~60-120 seconds. Users lose terminal access
silently. The fix is server-side keepalive (TERM-01) and client-side reconnect (TERM-02).

Output: Modified `server/routes/terminal.js` with ping/pong interval. Modified
`TerminalOverlay` in `client/src/pages/GSD.tsx` with reconnect logic that reuses the
existing xterm Terminal instance (no re-init flicker).
</objective>

Key existing code:

`server/routes/terminal.js` — the terminal WebSocket is created via `wss.handleUpgrade`.
After upgrade, the server spawns a `node-pty` process and forwards data bidirectionally.
There is currently NO ping/pong mechanism and NO per-connection timeout tracking.

`server/websocket.js` (the main /ws WebSocket) already has a heartbeat pattern to copy:
```js
ws.isAlive = true;
ws.on('pong', () => { ws.isAlive = true; });
// setInterval every 30s — if !ws.isAlive: terminate; else ws.isAlive=false; ws.ping()
```
Use the same pattern in terminal.js, but with a 20-second interval (more aggressive than
the 30s main WS because terminal proxies are less tolerant of idle).

`client/src/pages/GSD.tsx` TerminalOverlay — the ws.onclose handler currently only writes
an error message to the terminal. The reconnect logic needs to:
1. Write "\r\n[Reconnecting...]\r\n" to the existing terminal
2. Wait 2 seconds, then create a new WebSocket to the same URL
3. Wire up all the same message/close handlers on the new WebSocket
4. Replace wsRef.current with the new WebSocket
5. Cap retries at 10 to avoid infinite loops (write "Connection failed" after cap)
6. Reset retry count on successful open
Important: do NOT recreate the xterm Terminal instance on reconnect. Reuse termRef.current
so the terminal history is preserved.

Key changes:

1. Add refs before the async setup:

```ts
const retryCountRef = useRef(0);
const MAX_RETRIES = 10;
```

2. Extract WebSocket construction into an inner `connectWs` function:
```ts
function connectWs(terminal: Terminal, wsUrl: string) {
  const ws = new WebSocket(wsUrl);
  wsRef.current = ws;

  ws.onopen = () => {
    retryCountRef.current = 0;
    setConnected(true);
    ws.send(JSON.stringify({ type: 'resize', cols: terminal.cols, rows: terminal.rows }));
  };

  ws.onmessage = (event) => { /* existing logic */ };

  ws.onclose = (event) => {
    setConnected(false);
    if (event.code === 4004) {
      terminal.write('\r\n\x1b[31mSession is not active.\x1b[0m\r\n');
      return;
    }
    if (event.code === 4005) {
      terminal.write('\r\n\x1b[31mTerminal backend unavailable (node-pty not installed).\x1b[0m\r\n');
      return;
    }
    if (event.code === 1000) return; // clean close (e.g. user navigated away)
    if (cancelled) return; // component unmounted
    if (retryCountRef.current >= MAX_RETRIES) {
      terminal.write('\r\n\x1b[31mReconnect failed after 10 attempts.\x1b[0m\r\n');
      return;
    }
    retryCountRef.current += 1;
    terminal.write(`\r\n\x1b[33mReconnecting... (attempt ${retryCountRef.current})\x1b[0m\r\n`);
    setTimeout(() => {
      if (!cancelled) connectWs(terminal, wsUrl);
    }, 2000);
  };

  ws.onerror = () => {
    // Let onclose handle it — onerror always precedes onclose
  };

  return ws;
}
```

3. Replace the existing `const ws = new WebSocket(wsUrl)` and its event handlers with a
   call to `connectWs(terminal, wsUrl)`.

4. The `terminal.onData` handler must reference `wsRef.current` (not the closed `ws`

```ts
terminal.onData((data) => {
  const activeWs = wsRef.current;
  if (!activeWs || activeWs.readyState !== WebSocket.OPEN) return;
  // ... existing filter logic
  activeWs.send(data);
});
```
   Apply the same `wsRef.current` pattern to `terminal.onSelectionChange`,
   `handleResize`, and the scroll/touch/pinch handlers that call `ws.send`.

5. In the cleanup function returned from useEffect, change `ws.close()` references to
   `wsRef.current?.close()` if not already done.

Do NOT change the xterm Terminal initialization, fit addon, or theme logic.

# Plan 63-01: Fix Global Permissions and Launch Command

## Goal

Ensure all Claude Code sessions on this Hetzner server run fully autonomously — no permission
prompts for GSD skills or tool use — both for currently running sessions and future sessions
started via the dashboard.

## Tasks

### Task 1 — Add Skill(gsd-*) to ~/.claude/settings.json

Edit `~/.claude/settings.json` permissions.allow to include `"Skill(gsd-*)"`.

This takes effect for all running sessions immediately (no restart needed).

**File:** `/root/.claude/settings.json`
**Change:** Add `"Skill(gsd-*)"` to the `permissions.allow` array

### Task 2 — Fix reopen-tmux to always pass --dangerously-skip-permissions

Remove the isRoot branch in `server/routes/gsd.js`. Always launch with the flag.

**File:** `server/routes/gsd.js` line ~360
**Before:**
```js
const isRoot = process.getuid && process.getuid() === 0;
const claudeCmd = isRoot ? 'claude --effort medium' : 'claude --effort medium --dangerously-skip-permissions';
```
**After:**
```js
const claudeCmd = 'claude --effort medium --dangerously-skip-permissions';
```

### Task 3 — Audit and fix per-project settings.local.json

Check all projects under `/data/home/` for settings.local.json files.
- Ensure each has at minimum `Skill(gsd-*)` (or confirm global settings covers it)
- zoho-todoist-sync specifically: update to include `Skill(gsd-*)`
- gsddashboard: update to include `Skill(gsd-*)`

### Task 4 — Restart gsd-dashboard and verify

```bash
pm2 restart gsd-dashboard
curl -s -o /dev/null -w "%{http_code}" http://localhost:4820/api/health
```

Verify health check returns 200.

### Task 5 — Smoke test

Send `/gsd-quick` to the zoho-todoist-sync tmux session via the dashboard and confirm no
permission prompt appears.

- [ ] `~/.claude/settings.json` contains `Skill(gsd-*)` in allow list

- [ ] No permission prompts for GSD skills in running sessions

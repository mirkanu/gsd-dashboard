<objective>
Reduce tmux keystroke latency caused by swap thrashing under concurrent Claude Code sessions.

Purpose: The VPS has 3.7GB RAM with ~1.7GB RSS consumed by Claude processes. Default swappiness=60 causes aggressive SSD swapping, introducing keystroke lag in tmux panes. A compressed in-memory zram device at higher swap priority dramatically reduces I/O-bound stalls.

Output: Kernel VM parameters tuned, 1.9GB lz4-compressed zram swap active at priority 100, persistent across reboots, documented in the hetzner-vps repo.
</objective>

<task type="auto">
  <name>Task 2: Set up zram swap device (persistent)</name>
  <files>/etc/systemd/system/zram-swap.service</files>
  <action>
First check if the zram-config package is available and functional:
```bash
apt-get install -y zram-config 2>&1 | tail -5
systemctl is-active zram-config 2>/dev/null
swapon --show
```

If zram-config installed correctly and a zram device already appears in `swapon --show` with priority >= 5, skip systemd service creation — the package handles persistence.

If zram-config is NOT available or does not create a zram swap device, use zramctl directly:

1. Load the zram kernel module:
```bash
modprobe zram
```

2. Create /etc/systemd/system/zram-swap.service:
```ini
[Unit]
Description=zram swap (lz4, 1.9GB, priority 100)
After=local-fs.target

[Service]
Type=oneshot
RemainAfterExit=yes

ExecStart=/bin/bash -c '\
  modprobe zram && \
  zramctl --find --size 1900M --algorithm lz4 && \
  ZDEV=$(zramctl --find 2>/dev/null || echo /dev/zram0) && \
  mkswap $ZDEV && \
  swapon -p 100 $ZDEV'

ExecStop=/bin/bash -c '\
  for dev in $(swapon --show=NAME --noheadings | grep zram); do swapoff $dev; done && \
  zramctl --reset /dev/zram0 2>/dev/null; true'

[Install]
WantedBy=multi-user.target
```

3. Enable and start:
```bash
systemctl daemon-reload
systemctl enable --now zram-swap.service
```

4. Confirm zram is active:
```bash
swapon --show
```
Must show a /dev/zram* entry with priority 100.

Note on zramctl --find race: if zramctl --find returns before the device node appears, add `sleep 0.5` before mkswap. Adjust if needed.
